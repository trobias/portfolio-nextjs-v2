# Accessibility compliance

Target WCAG 2.2 AA unless the project specifies another standard.

1. Inspect semantics, landmarks, heading order, labels, accessible names, relationships, status messages, and error identification.
2. Verify complete keyboard operation, logical focus order, visible focus, skip navigation, modal focus containment, and focus restoration.
3. Check text and non-text contrast, zoom/reflow, touch target size, orientation, responsive layout, and content exposed on hover or focus.
4. Respect reduced motion; avoid flashing, vestibular effects, autoplay, and animation required to understand content.
5. Test forms, validation, authentication, timeouts, drag interactions, media alternatives, and dynamic updates.
6. Prefer native HTML. Use ARIA only when native semantics are insufficient.
7. Report automated findings as leads and confirm important issues manually before claiming compliance.

Do not remove functionality or redesign product behavior without approval.
